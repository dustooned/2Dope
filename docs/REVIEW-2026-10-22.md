## Findings, in suggested order

### 1. Active-layer rendering ignores layer opacity and blend

**Confirmed in source and browser for opacity.** In Draw, a black stroke remained fully visible after setting its layer to 0% opacity. `src/app.ts:5540` paints active pixels separately from the shared compositor, and the nongroup path at `src/app.ts:5656` calls `paintMasked(g)` without the layer opacity/blend. Blend omission is source-confirmed; a visual blend-mode comparison was not performed.

The shared compositor in `src/view/composite.ts` has the flatten-then-apply-layer-properties path. Unifying live drawing with this path needs to preserve live raster/vector previews, masks, clipping, onions, part transforms and residency.

Screenshot: `C:/Users/dusto/.codex/visualizations/2026/10/22/01a165f6-3d4e-7ff2-8532-902366500f5b/2dope-zero-opacity.png`.

### 2. The active paint plane cannot visually reach zero opacity

**Confirmed in source and browser.** Setting Line opacity to 0% left a faint stroke visible. `src/app.ts:5681` uses `Math.max(a, 0.25)` for the target plane, including when its visibility is off. This creates a mismatch between the controls and Draw's display. Any intentional editing aid should have an explicit presentation rather than silently overriding the setting.

### 3. Timing repeats controls across three surfaces

**Confirmed in the browser at Simple.** Play and Onion appear in the top tools and bottom transport. Hold 1–4 and drawing-role controls appear in both the top options and X-sheet; frame actions repeat in the tools, transport and X-sheet. This supports the roadmap's cleanup diagnosis. The Draw paint target and bucket also both use the label Fill. The flipbook track label was visibly crowded by its eye/tick box.

### 4. Flipbook zoom reconstructs the full strip

**Confirmed mechanism; performance impact not measured.** `src/ui/flipmode.ts:225` invalidates the signature on zoom; `update()` calls `build()`, which replaces grid children and reconstructs ruler/track content. The pinch handler calls this repeatedly. There was no 1,000-frame benchmark, CPU-throttled trace or real-device timing in this review. Treat stutter as a risk, not a measured result.

### 5. The maintenance handoff understates the current product

**Confirmed against current source.** `HANDOFF.md` still describes the 309-test baseline and says clipping masks and effect stacks are unbuilt. Current code implements both. Its old file-format/invariant wording also mentions schema 2 and only two optional fields; current `src/io/schema.ts` uses schema 3 and supports additional layer fields including masks, clipping, effects, still and notes. `ARCHITECTURE.md` is partly updated but still contains old Flip and interface-level descriptions. Package description remains the Milestone 0 prototype description.

## Implemented versus proposed

Current user-facing modes are **Story, Draw, Timing, Motion, Share**. Draw owns the flipbook; Share is a UI flow over the existing workspace model. Current interface levels are **Focus, Simple, Full**.

The separate **Animate** workspace, picture shelf, consolidated per-mode control registry, dockable **Advanced** interface and canvas-based rail are proposals in `docs/next-phase.md`, not the current implementation.

Newer implemented code includes clipping/alpha lock, masks and paint stacks; effect stacks and dither/noise/texture/displacement; gradients and drawing adjustments; GIF/PSD/OpenRaster import; brush collections/import; floating Reference and mini flipbook; notes and hand-in stamping; transparent WebM/APNG output; and deferred Pencil strokes while drawings load. Presence in source is not end-to-end verification of each feature.
